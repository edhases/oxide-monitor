## 1. Інформаційна архітектура вікна налаштувань (Win11 NavigationView)

Класична проблема TrafficMonitor — діалог налаштувань із десятками дрібних чекбоксів у стилі MFC 2005 року, де важко зрозуміти, як зміна параметра вплине на віджет.

### 1.2. Анти-перевантаження (UX-принципи)
- **Progressive Disclosure:** у кожній секції видно 3–5 головних контролів; тонкі налаштування (наприклад, `HDR-safe opaque`, `baseline_offset`, `decimal_separator`, `decay_factor` для sparkline) сховані під `▸ Розширені параметри`.
- **Швидкий пошук (`Ctrl+K` або поле в сайдбарі):** фільтрує налаштування за українською, англійською або технічною назвою (напр. запит `шрифт`, `mica`, `nvme`, `hwinfo`, `game`) і підсвічує потрібну картку.
- **Undo / Redo стек (`Ctrl+Z` / `Ctrl+Y`):** зберігає останні 50 станів `draft_config` у пам'яті `oxide-settings.exe` — користувач може сміливо експериментувати з конструктором.
- **Повна i18n через Fluent (`.ftl`):** усі підписи налаштувань, описи пресетів і підказки беруться з `oxide-core/locales/{uk,en,ru}.ftl` (дефолт `uk`), розширюючи вже наявний `Localizer`.

## 2. Інтерактивний вибір датчиків та аліасів (`Hardware Discovery UI`)

У `oxide-core::Snapshot` уже збираються вектори `gpus: Vec<GpuSample>` і `disks: Vec<DiskSample>`, а `NetworkSampler` знає повну таблицю `AdapterInfo` з `GetIfTable2`. Для вікна налаштувань `oxide-monitor.exe` додатково передає по Named Pipe структуру **`HardwareInventory`** (оновлюється 1 раз на секунду лише поки відкриті налаштування).

### 2.1. Мережеві адаптери
```
┌────────────────────────────────────────────────────────────────────────────┐
│ Мережевий адаптер за замовчуванням:  (●) Авто-вибір (активний маршрут)     │
│                                      ( ) Обрати конкретний адаптер нижче   │
├────────────────────────────────────────────────────────────────────────────┤
│ ● [Активний]  Wi-Fi (Intel Wi-Fi 6 AX200)          ↑ 1.2 Mb/s  ↓ 18.4 Mb/s │
│               1201 Mbps • Підключено               Аліас: [ Wi-Fi       ]  │
│                                                                            │
│ ○             Ethernet (Realtek PCIe GbE)          ↑ 0.0 Mb/s  ↓  0.0 Mb/s │
│               Відключено                           Аліас: [ LAN         ]  │
│                                                                            │
│ ▸ Показати віртуальні та VPN-адаптери (4: Tailscale, vEthernet WSL, ...)   │
└────────────────────────────────────────────────────────────────────────────┘
```
- Автоматично виділяє активний маршрут (`GetBestInterface` + `is_auto_candidate()`).
- Віртуальні, Hyper-V, WSL, VPN-інтерфейси за замовчуванням згорнуті, але доступні в один клік (якщо користувач хоче бачити окремо трафік VPN-тунелю поруч із основним Wi-Fi!).
- Фіксація вибору зберігає **LUID + ім'я** (захист від втрати після resume/перепідключення, див. `05_current_setup_audit.md` §9.1).

### 2.2. Відеокарти (Multi-GPU: iGPU + dGPU окремо)
```
┌────────────────────────────────────────────────────────────────────────────┐
│ [dGPU • Primary] NVIDIA GeForce GTX 1650          Load: 12%  42 °C  NVML   │
│                  VRAM: 0.8 / 4.0 GB               Аліас: [ GTX 1650   ]    │
│                  [+ Додати Load у віджет]  [+ Додати Temp]  [+ VRAM]       │
├────────────────────────────────────────────────────────────────────────────┤
│ [iGPU]           AMD Radeon(TM) Graphics          Load:  5%  47 °C  ADLX   │
│                  VRAM: 0.4 / 0.5 GB               Аліас: [ iGPU       ]    │
│                  [+ Додати Load у віджет]  [+ Додати Temp]                 │
└────────────────────────────────────────────────────────────────────────────┘
```
- Користувач бачить живі цифри й джерело (`NVML` / `ADLX` / `Level Zero` / `PDH`) біля кожної карти.
- Можна однією кнопкою додати у віджет і `iGPU`, і `dGPU` одночасно (або вибрати, яка карта є `primary`).

### 2.3. Накопичувачі (Multi-Disk із короткими аліасами)
```
┌────────────────────────────────────────────────────────────────────────────┐
│ [Disk 0 • NVMe]  Apacer AS2280P4U 1TB (C:)        Act:  2%   41 °C  Native │
│                  Критичний поріг: 95 °C           Аліас: [ NVMe       ]    │
│                  [+ Додати Temp у віджет]  [+ Активність %]                │
├────────────────────────────────────────────────────────────────────────────┤
│ [Disk 1 • SATA]  HGST HTS721010A9E630 (D:)        Act:  0%   —      SATA*  │

│                  [+ Додати Активність %]                                   │
└────────────────────────────────────────────────────────────────────────────┘
```
- Аліаси зберігаються у секції `[aliases]` файлу `config.toml` з ключем за моделлю/LUID (напр. `"Apacer AS2280P4U 1TB" = "NVMe"`), і миттєво відображаються як короткі підписи у віджеті та у Flyout-панелі.

### 2.4. CPU та температурні джерела
- Показує модель процесора, загальне навантаження (`% Processor Utility`), поточну частоту, а також прозорий селектор `CPU Temp Source`:
  - `Авто (Провайдер → ACPI)`
  - `Тільки точний провайдер (HWiNFO / LHM)` — `—` без провайдера
  - `ACPI Thermal Zone (best-effort ~)` — із живим показником (`48 °C~`) і чесним поясненням, що це температура платформної зони, а не ядер.
  - `Вимкнено`

## 3. Система пресетів та скінів

### 3.1. Вбудовані готові пресети (5 штук «з коробки»)

Усі пресети — це звичайні вбудовані TOML-файли (`include_str!`), які вантажаться в той самий рушій `Config v2` без жодних спеціальних «милиць» у рендерері:

1. **«Класичний 2-рядковий (TrafficMonitor)»** (`classic-2row`):
   - Макет: `flow_rows`, `rows = 2`, `column_major`, ~`294 × 35 px`, 8 текстових елементів (`↑`, `↓`, `CPU`, `MEM`, `GPU`, `CPU°`, `GPU°`, `NVMe°`).
   - Шрифт: `Segoe UI` 8 pt, `tabular-nums`, звична палітра кольорів (`#7FD37F`, `#F0C674`, `#7FBFEF`, `#F0A050`, `#E08080`).
   - Ідеальний дефолт для переходу з TrafficMonitor.

2. **«Мінімалізм 1 рядок (Ultra-Slim)»** (`minimal-1row`):
   - Макет: `flow_rows`, `rows = 1`, `transparent` фон + легка тінь тексту, ~`210 × 28 px`.
   - 4 елементи: `↓ 12.4M  ↑ 1.2M  CPU 14%  RAM 64%` (`short_mode = true`, `Segoe UI Variable` 9 pt).
   - Займає мінімум місця на сучасному Windows 11 таскбарі.

3. **«Геймерський з графіками (Telemetry Pro)»** (`gamer-sparklines`):
   - Макет: `grid` (2 рядки), висота `38 px`, ширина ~`380 px`.
   - Зліва: подвійний графік мережі `graph_only` (`row_span = 2`, 48 px ширини) + текстові `↑`/`↓`.
   - По центру й справа: `CPU` (`text_sparkline` фоном), `RAM` (`text_progress` тонка лінія знизу), `dGPU %` + `dGPU °C` + `CPU °C` із **плавним OKLab градієнтом** (`#4ADE80` → `#FACC15` → `#F87171` на порогах `55 °C / 75 °C / 88 °C`).

4. **«Windows 11 Fluent (Pills)»** (`win11-fluent`):
   - Макет: 2 рядки з 3 візуальними групами («пігулками») із `corner_radius = 6`, тонкою рамкою `1 px rgba(255,255,255,0.08)` (у Dark) або `rgba(0,0,0,0.08)` (у Light), напівпрозорий фон, системний колір акценту для прогрес-барів.
   - Автоматично підлаштовується під `SystemUsesLightTheme` Windows 11.

5. **«Компактний вертикальний / 3-рядковий»** (`vertical-stack`):
   - 1 колонка, 6–8 рядків (`72 × 180 px`), або 3 рядки для високих таскбарів. Підтримує радіальні кільця (`radial_ring`) для CPU/RAM/GPU.

### 3.2. Формат експорту та імпорту тем між користувачами

Пропонується два рівні пакування, обидва **суто декларативні (без виконуваного коду)**:

| Формат | Розширення | Коли використовувати | Вміст |
|---|---|---|---|
| **Текстовий пресет** | `.oxide-preset.toml` | Швидкий обмін у Discord/GitHub/Reddit (можна скопіювати навіть текстом через буфер обміну!) | Метадані (`[preset] name, author, version, min_app_version, description`) + підмножина візуальних секцій `[surface]`, `[layout]`, `[typography]`, `[format]`, `[[items]]`. **Не містить** приватних шляхів, `lhm_url`, LUID-адаптерів чи налаштувань автозапуску! |
| **Пакет теми (Скін)** | `.oxide-theme.zip` | Теми з кастомним фоном PNG, іконками або шрифтовою конфігурацією | `theme.toml` + `preview.png` (опційно) + `assets/*.png` (фон, іконки). |

**Безпека при імпорті `.oxide-theme.zip`:**
- Строгий білий список розширень усередині архіву: `.toml`, `.png`, `.svg`.
- Захист від Zip-Slip (`..` або абсолютні шляхи відхиляються).
- Ліміт розпакованого розміру `≤ 5 MB`, кількість файлів `≤ 32`.
- Валідація `theme.toml` через `Config::normalize()` (clamp розмірів, шрифтів, прозорості) + попередній перегляд у Live Preview **до** застосування.

## 4. Імпортер конфігурації та скінів зі старого TrafficMonitor

Велика частина перших користувачів Oxide Monitor мігруватиме саме з TrafficMonitor (як зафіксовано в `05_current_setup_audit.md`). Імпортер виділяється в чистий крейт **`oxide-import`** (без Win32-залежностей, 100% покривається unit-тестами).

### 4.1. Імпорт `config.ini` → `config.toml` v2

TrafficMonitor зберігає `config.ini` у UTF-8 (іноді з BOM) або UTF-16LE / ANSI (CP1251/GBK). Імпортер автоматично визначає кодування і мапить ключі:

| Ключ TrafficMonitor (`config.ini`) | Трансформація в `Oxide Monitor` (`config.toml` v2) | Примітки |
|---|---|---|
| `tbar_display_item` (бітова маска `u32`, напр. `255`) | Масив `[[items]]` із `visible = true` для встановлених бітів (`0=Up, 1=Down, 2=CPU, 3=Mem, 4=GPU, 5=CpuTemp, 6=GpuTemp, 7=HddTemp, 8=MbdTemp, 9=HddUsage, 10=CpuFreq, 11=TotalSpeed, 12=TodayTraffic`) | Біт `MbdTemp` мапиться в `external_sensor` із позначкою «потрібен провайдер». |
| `item_order` (`"0,1,2,..."`) | Сортування масиву `[[items]]` у точному порядку користувача | — |
| `task_bar_speed_unit` (`0/1/2`), `speed_unit_byte`, `speed_short_mode`, `hide_unit`, `hide_percent`, `separate_value_unit_with_space`, `digits_number` | Прямий 1:1 мапінг у секцію `[format]` | Повний паритет форматування |
| `item_space`, `vertical_margin`, `horizontal_arrange` | `[layout]` (`gap_x`, `gap_y`, `rows = 1` якщо `horizontal_arrange = true`, інакше `2`) | — |
| `tbar_font_name`, `tbar_font_size`, `tbar_font_style` | `[typography.label]` / `[typography.value]` / `[typography.unit]` | Біти `style`: `1=Bold (700)`, `2=Italic` |
| `tbar_text_color` (десятковий `COLORREF` або список через кому), `tbar_back_color`, `tbar_transparent_color` | Конвертація `0x00BBGGRR` → `#RRGGBB` у `items[i].color_rule` і `[surface]` | `R = v & 0xFF`, `G = (v >> 8) & 0xFF`, `B = (v >> 16) & 0xFF` |
| `up_string`, `down_string`, `cpu_string`, `memory_string`, `gpu_string`, `*_temp_string` | `items[i].label` | Зберігаються кастомні підписи користувача |
| `window_offset_top`, `window_offset_left`, `taskbar_left_space_win11`, `taskbar_right_space_win11` | `[taskbar]` (`x_offset`, `y_offset`, `left_space`, `right_space`) | — |
| `double_click_action` (`0=TaskMgr, 1=TrafficHistory, 2=Settings, ...`) | `[interactions].double_click` | — |
| `hard_disk_name` (напр. `"Apacer AS2280P4U 1TB"`) | Прив'язка `disk_temp`/`disk_activity` за `model_hint` | Збіг із реальним `PhysicalDriveN` |
| `auto_adapt_light_theme` | `[general].theme = "auto"` | — |
| `show_netspeed_figure`, `show_status_bar`, `cm_graph_type` | `visual.mode = "text_sparkline"` або `"text_progress"` (`bar_background`) | Перекладається у сучасні візуальні режими |
| `hardware_monitor_item` | **Не вмикає драйверів автоматично!** | Додається запис у звіт імпорту: «У TrafficMonitor використовувався LHM/PawnIO; для CPU Temp увімкніть HWiNFO/LHM у вкладці Провайдери». |

### 4.2. Імпорт скінів `skin.xml` та legacy `skin.ini`

- **`skin.xml` (TrafficMonitor ≥ 1.80, UTF-8):** парситься легким безпечним крейтом `roxmltree` (zero-copy, без вразливостей XXE).
  - `<skin>/<font name size style>` → `[typography]`.
  - `<skin>/<text_color>` + `<specify_each_item_color>` → конвертація списку десяткових `COLORREF` у `items[i].color_rule`.
  - `<skin>/<display_text>/<up|down|cpu|memory|gpu|cpu_temperature|gpu_temperature>` → `items[i].label`.
  - `<layout no_label="1">` → приховування лейблів у всіх елементах.
  - `<layout>/<layout_s>` та `<layout_l>` (`x`, `y`, `width`, `align`, `show`) → конвертуються в режим абсолютних координат або `grid`-макет (`layout.mode = "absolute_skin"` або автоматична кластеризація по `y` у рядки для таскбара!).
  - `background.png` / `background.bmp` (якщо є в папці скіна) → копіюються в `assets/` імпортованої теми.
- **`skin.ini` (старі скіни):** парситься секціями `[skin]` та `[layout]` за тими ж правилами конвертації `COLORREF` і координат.

### 4.3. UX майстра міграції (3 кроки)
1. **Вибір джерела:** кнопка «Імпорт із TrafficMonitor» пропонує або перетягнути `config.ini` / папку скіна прямо у вікно, або вибрати файл через стандартний Windows File Dialog (`IFileOpenDialog` / `rfd`).
2. **Звіт про сумісність (Import Summary):** чіткий список трьох категорій:
   - ✅ **Перенесено точно** (напр. 8 елементів, порядок, шрифт `Segoe UI 8pt`, кольори, одиниці `Mb/s`, зсуви).
   - ⚠️ **Адаптовано** (напр. `background color-key` переведено у `per-pixel alpha` для коректної роботи з HDR).
   - ℹ️ **Пропущено з міркувань безпеки / поза скоупом** (напр. `OpenHardwareMonitorApi.dll` / `PawnIO` — не імпортується автоматично; посилання на налаштування HWiNFO/LHM).
3. **Прев'ю та застосування:** результат одразу відкривається в Live Preview як чернетка; користувач може підкоригувати деталі та натиснути «Зберегти» або «Скасувати».
