# Localization (i18n)

Oxide Monitor uses **Fluent** (`.ftl`), not JSON/TOML/YAML. Fluent is designed for natural language:
plural categories, gender, punctuation, placeables and a fallback chain are part of the format, while
JSON/TOML/YAML force translators to encode grammar in flat strings.

## Files

```
crates/oxide-core/locales/en.ftl
crates/oxide-core/locales/uk.ftl
crates/oxide-core/locales/ru.ftl
crates/oxide-core/src/i18n.rs
```

Resources are embedded with `include_str!`; there is no runtime locale-file lookup and no way to
inject a malicious translation file. `Localizer` always keeps English as a secondary bundle.

## Selecting a language

`%APPDATA%\OxideMonitor\config.toml`:

```toml
[general]
language = "uk"   # uk | en | ru
```

`uk` is the default. Unknown codes fall back to English.

## Current keys

| Key | Usage |
|---|---|
| `app-name` | product name |
| `tray-tooltip` | tray tooltip |
| `menu-show` / `menu-hide` | toggle label |
| `menu-open-config` | open config |
| `menu-exit` | exit |
| `hidden-notice-title` / `hidden-notice` | balloon shown after explicit hide |

The UI labels inside the widget (`CPU:`, `MEM:`, …) are user-configurable display strings, not
localization keys; defaults are language-neutral.

## Adding a language

1. Add `locales/<code>.ftl` with the same keys.
2. Add a variant to `Language` and its `id()` / `source()` match arms in `i18n.rs`.
3. Add a unit test for at least `menu-exit` and the hidden-notice text.
4. Run `cargo test -p oxide-core`.

Example Fluent plural (future):

```ftl
provider-stale =
    { $seconds ->
        [one] Updated { $seconds } second ago
       *[other] Updated { $seconds } seconds ago
    }
```

Use `Localizer::text` for simple messages; add a `text_with_args` helper when placeables are needed.
